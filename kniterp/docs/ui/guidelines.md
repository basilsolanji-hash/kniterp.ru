# Правила интерфейса knitERP (для всех сессий)

Сессия 5 «Интерфейс», ТЗ `docs/tz/ui-review.md`. Решения — D800–D899 в `docs/decisions.md`. Новый экран делается по этим правилам;
отступление — с записью решения.

## 1. Каркас и меню
- Экран открывается из меню не дальше 3 нажатий. Новый экран — строка `I(адрес, название, право, подзаголовок)` в своём разделе
  `MainLayout.Groups`; частый — ещё и в `MainHrefs` (в меню раздела 3–7 пунктов, остальное — на странице раздела `section/{ключ}`).
- Настройки модуля — только в группе `settings` (подзаголовок `SModules`); в меню — один пункт «Настройки» (D808).
- Пунктов «скоро» нет. Пункт без права не показывается — но сервер всё равно проверяет право (`IAccessGuard.DemandAsync`).
- Страница стартует только после меню: `_access` в `MainLayout` присваивается последним; у вкладки один DbContext — компонент не
  запускает параллельные вызовы сервисов.
- Каждый `@page` — строка в `docs/ui/screens.md` (проверяет `ScreenInventoryTests`).

## 2. Заголовок и навигация
- Один `h1` на экран; заголовки дальше по порядку (`h2`, `h3`).
- Карточка: ссылка назад на список над заголовком («← Номенклатура») или хлебные крошки.
- Без права изменения (или запись в архиве / закрыта) — `<ReadOnlyNote When="…" />` под заголовком, поля неактивны.

## 3. Кнопки и действия
- Одно основное действие (цветная кнопка), остальные — `class="secondary"`.
- Кнопка блокируется до ответа сервера (D29); «успех» — только после ответа.
- Неактивная не из-за ожидания кнопка объясняет почему: `title` с причиной (у `ConfirmButton` — `Title`), у главной кнопки — ещё и
  видимо рядом: `<WhyDisabled When="@(cond)">@L("…")</WhyDisabled>` (на телефоне подсказки при наведении нет).
- Необратимое (архив, отмена, сторно, блокировка, выдача прав) — `ConfirmButton` с вопросом, необратимость названа прямо.
- Иконка без подписи — обязательно `aria-label` и `title`.
- Доступное имя кнопки не совпадает с кнопками страницы, если кнопка в общей шапке («Создать новое», а не «Создать»).

## 4. Формы
- Подпись у каждого поля (`<label>`), единицы рядом, обязательные отмечены, ошибки — у поля и понятным языком; введённое не теряется.
- Даты по умолчанию — «сегодня организации»: `TimeZones.Today(CurrentAccess.TimeZoneId)`, не `DateTime.Today` (время сервера).
  Необязательная дата может быть пустой, если пусто значит «без срока».
- Пароли и токены — `type="password"`, `autocomplete` по назначению; токен не попадает в адрес, журнал и снимки.

## 5. Списки и таблицы
- Поиск, фильтры (выбранные видны, сбрасываются одним нажатием), постраничность для больших списков.
- Числа и деньги — по правому краю (`class="num"`), с разделителями разрядов; даты — в формате пользователя.
- Пустой список — что это за экран и одна кнопка «Создать первый…».

## 6. Телефон (390 px)
- Без горизонтальной прокрутки и перекрытий; цели нажатия не меньше 44 px (D801); нижняя панель и помощник не закрывают кнопки.
- На телефоне меню открывает «Ещё» в нижней панели; в e2e:
  `page.Locator("nav.bottom-nav").GetByRole(AriaRole.Button, new() { Name = "Ещё" })`.

## 7. Тёмная тема и доступность
- Цвета — только переменные темы (`var(--text)`, `var(--bg)`, `var(--line)`…), без жёстких белых/чёрных фонов.
- Контраст текста не ниже 4,5:1 (WCAG 2.2 AA); видимый фокус; всё доступно с клавиатуры, Escape закрывает меню и диалоги.
- Ошибки — `role="alert"`, сообщения — `role="status"`, вкладки — `role="tab"`.
- «Уменьшить движение» — без анимаций.

## 8. Тексты и переводы
- Каждый текст — через `L("…")`, перевод на be/kk/uz (`bash .claude/skills/kniterp-translations/missing.sh` → MISSING 0, STALE 0).
- Без внутренних кодов и английских слов; одна терминология во всей программе.

## 9. Безопасность
- Скрытая кнопка — не защита. В разметке и ответах нет данных, которые пользователю не положены.
- Без встроенных скриптов (CSP `script-src 'self'`), без `MarkupString` с текстом пользователя; внешние ссылки —
  `rel="noopener noreferrer"`.
- Никаких реальных персональных данных, паролей и токенов в тестах и снимках.
