# Находки проверки интерфейса (этап 2 ТЗ `docs/tz/ui-review.md`)

Сессия 5 «Интерфейс». Важность: **блокирует** — нельзя выполнить работу; **мешает** — можно, но с трудом или ошибками;
**косметика** — вид. Снимки — в папке артефактов e2e (в репозиторий не кладутся). Статус: исправлено (решение) / передано модулю /
принято как есть (почему) / предстоит.

## Как искали
1. Автоматический обход 107 экранов без параметров в адресе (опись `docs/ui/screens.md`) Владельцем на 1440 и 390 px, в светлой и
   тёмной теме: ошибки JavaScript, горизонтальная прокрутка, заголовок `h1`, текст исключения, время открытия, axe-core 4.10.3
   (нарушения serious/critical). Тот же обход закреплён тестом `AllScreensE2ETests` (D890).
2. Ручной просмотр меню, верхней панели, блока пользователя, главной, карточек и форм с неактивными кнопками на 1440 и 390 px.

Итог автоматического обхода после исправлений: ошибок JS — 0, текста исключений — 0, медленных экранов (> 1,5 с вместе с ожиданием
подключения) — 0; горизонтальная прокрутка — только у двух печатных листов на 390 px.

## Предстоит (следующие пакеты)
- Ручная оценка каждого экрана по 4.1: порядок полей, автофокус, пустые состояния «Создать первый…», сброс фильтров,
  итоги и постраничность — по разделам в порядке этапа 3 (вход → главная → продажи → закупки → склад → деньги → …).
- Раздел 0, п. 5–7: «Свой вариант» в выпадающих списках (опись `docs/ui/lookups.md`), открытие объекта нажатием на строку,
  запоминание фильтров, предупреждение о несохранённых изменениях, Ctrl+S.
- Экраны с параметрами в адресе (карточки) — в обход по данным теста.
- Обход ролью Кладовщик (сейчас — Владелец).
