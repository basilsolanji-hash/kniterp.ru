# Интерфейс (сессия 5, `claude/ui-review`) — сообщения другим сессиям

Ветка `claude/ui-review` от базы `claude/fervent-volta-3pn88r`. Решения — D800–D899 (`docs/decisions.md`, раздел «Интерфейс всех экранов»).
Мои файлы: `MainLayout`, меню, верхняя панель (`QuickBar`), блок пользователя (`ProfileMenu`), `SideFooter`, общие стили `App.razor`,
`Components/Shared/*`. Экраны `Dev*.razor` пересматривает сессия «Разработка».

## Что изменилось для всех (13.10.2026)
- **Меню (D800, `docs/ui/menu.md`).** Пункт меню — `I(адрес, название, право, подзаголовок)`; подзаголовки — константы `SDocs`, `SPrices`,
  `SReports`, `SOrg`, `SModules`, `SExchange`, `SControl`. Пункты без права больше не показываются (сервер проверяет как раньше);
  пунктов «скоро» нет. Новый экран модуля — одной строкой в своём разделе; настройки модуля — в «Настройки → Модули».
- **Верхняя панель и профиль (D801, D802).** Профиль — в правом краю верхней панели, а не внизу меню слева.
- **Без предварительной отрисовки (D803).** Интерактивные страницы рисуются только после подключения схемы. В e2e после `goto` по-прежнему
  ждите готовности (`ready(page)` / подключения Blazor); статического HTML страницы до подключения больше нет.
- **Цели нажатия 44 px** на сенсорных экранах (D801) — не задавайте кнопкам и полям `min-height` меньше.

- **Меню v2 (D805).** `MainLayout.Groups`, `NavGroup`, `NavItem` — публичные (их читает страница раздела `section/{ключ}`).
  В меню видны 3–7 частых пунктов раздела (`MainHrefs`), остальные — на странице раздела. Новый частый экран — добавьте адрес в `MainHrefs`.
  На телефоне (≤899 px) меню открывает «Ещё» в нижней панели `nav.bottom-nav`; кнопка «Меню» в шапке скрыта. В e2e для телефона
  открывайте меню так: `page.Locator("nav.bottom-nav").GetByRole(AriaRole.Button, new() { Name = "Ещё" })`.
- **Верхняя панель v2 (D806).** Порядок: Поиск, Создать (меню «новых» действий из `DashboardActions` по правам), закреплённые инструменты.
  У каждого значка подсказка и `aria-label`. На телефоне — Поиск, Создать, Уведомления и «Ещё».
- **Блок пользователя v2 (D807).** Кнопка: аватар, имя, «должность · организация». Пункты: «Профиль и пароль» (`security#password`),
  «Сессии и устройства» (`security#devices`), «Обучение», «Поддержка». «Рабочий день» внизу меню свёрнут в одну строку.

- **«Настройки» — один пункт (D808).** Пункт ведёт на `MainLayout.SettingsHref` (сейчас `section/settings` — плитки из группы
  `settings` в `MainLayout.Groups`). **Сессии № 1:** когда будет страница `/settings` (этап 2б), сообщите — сменю адрес; плитки
  на ней можно строить из той же группы `settings` (подзаголовки `SOrg`, `SModules`, `SExchange`, `SControl`), чтобы список настроек был один.
  Новая настройка модуля — строка `I(адрес, название, право, SModules)` в группе `settings`.

- **Причина у неактивного действия (D809).** Неактивная не из-за ожидания кнопка получает `title` с причиной
  (у `ConfirmButton` — параметр `Title`); у главных кнопок причина видна рядом: `<WhyDisabled When="@(cond)">@L("…")</WhyDisabled>`.
  Страница или карточка без права изменения — `<ReadOnlyNote When="@(!CanEdit)" />` под заголовком. Пожалуйста, делайте так же в новых экранах.
- **«Сегодня» организации (D809).** Дата по умолчанию — `TimeZones.Today(CurrentAccess.TimeZoneId)`, не `DateTime.Today` (время сервера).
- **Опись экранов (`docs/ui/screens.md`).** Новый `@page` — новая строка описи, иначе падает `ScreenInventoryTests`.

## Вопросы к модулям
- **«Разработка» (`DevModelsPage`, доска `.dev-board`).** Доска прокручивается, но не получает фокус с клавиатуры (axe
  `scrollable-region-focusable`, serious). Предложение: `<div class="dev-board" role="region" tabindex="0" aria-label="@L("Доска моделей")">`
  — как сделано у доски сделок CRM (D810). Пока не исправлено, нарушение помечено в `AllScreensE2ETests.PassedToModules`.
- **«Разработка» (`/print/dev/label`).** На 390 px лист этикетки шире экрана на 53 px — для печатной формы допустимо, но панель
  кнопок печати можно переносить по строкам.
- **Сессии № 1 — этикетки (запрос владельца 13.10, п. 5; разметку и вид делает интерфейс).** Сейчас (D316): шаблон — размер 15–150 мм,
  рулон или A4 (колонки × ряды), 13 полей, 6 образцов. Нужно в Domain/Application (`KnitErp.Domain/Catalog/Labels.cs`, сервис шаблонов):
  1. **Тип этикетки** в шаблоне: товарная, вшивная/составник, ценник (обычный, акция со старой ценой), «Честный ЗНАК», партия пряжи,
     короб/упаковка, ячейка склада, маркетплейс (товар WB/Ozon, короб/поставка FBO), паспорт изделия, образец «Разработки».
  2. **Новые поля** `LabelField`: состав (ТР ТС 017), символы ухода ISO 3758 (набор кодов), размер, рост/обхват, цвет, изготовитель
     и адрес, дата изготовления, код маркировки (DataMatrix) и GTIN, штрихкод площадки (WB/Ozon), количество в коробе, размерный ряд,
     вес нетто/брутто, получатель, ячейка/стеллаж, старая цена, логотип организации.
  3. **Поворот** 0/90°, **поля и зазоры** (мм), **разрешение принтера** 203/300 dpi (для точного размера штрихкода), **свой размер**
     до 150×150 мм уже есть; сетки A4 2×5, 3×7, 4×10, 5×13 — образцами.
  4. **Образцы** (`LabelTemplate.Presets`): 30×20, 40×25, 43×25, 58×30, 58×40, 58×60, 75×120, 100×100, 100×150 мм и листы A4 выше.
  5. **Генератор DataMatrix** (в Domain, как EAN-13/Code128) — для «Честного ЗНАКа»; код маркировки — из документа, а не вручную.
  6. **Печать по количеству** из поступления (по одной на штуку), из заказа и отгрузки — метод сервиса, отдающий строки с количеством.
  Когда появится — сделаю редактор (сетка блоков, шрифт, логотип, предпросмотр 1:1) и страницы печати.
- **Сессии № 1 — падение вкладки при уходе со страницы, которая ещё загружается (важность: блокирует, редко).** В журнале
  13.10: `InvalidOperationException: A second operation was started on this context instance` — `DashboardPage.OnInitializedAsync`
  (строка 225) ещё грузила данные, а пользователь уже вернулся «Назад» на складские документы
  (`StockDocumentsPage.OnParametersSetAsync` → `ListVisibleWarehousesAsync`). У вкладки один `DbContext` (CLAUDE.md), и загрузка
  прежней страницы не отменяется при переходе — новая страница стартует параллельно; схема Blazor падает, пользователь видит
  «Ошибка, перезагрузите». Воспроизводится нестабильно, чаще всего так: **открыть главную и сразу перейти в другой раздел** — заголовок главной виден сразу, а `DashboardService.GetAsync` (`DashboardPage.OnInitializedAsync`, строка 225) ещё идёт; следующая страница (`StockDocumentsPage` → `ListVisibleWarehousesAsync`, также `CounterpartyCardPage` → `ContractsAsync`: «Cannot access a disposed context») стартует параллельно. В e2e это 1 падение из 3 прогонов. Предложение:
  контекст базы на страницу (`OwningComponentBase`/`IDbContextFactory` в сервисах) или очередь операций на контекст вкладки;
  интерфейс со своей стороны: фильтры не восстанавливаются скриптом (D816); для главной — семафор вкладки `TabLoadGate`, переход ждёт конца её загрузки (D820). Другие тяжёлые страницы можно подключить к `TabLoadGate` так же, но надёжное решение — в сервисах.
