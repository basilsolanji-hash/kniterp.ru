# Пилот knitERP на фабрике (версия 2, 12.10.2026)

Цель пилота — фабрика 4–8 недель ведёт учёт только в knitERP: склад, закупки, продажи, деньги, производство и сотрудники
(CRM и «Разработка» — по желанию Владельца, с первого дня или со второй недели). Параллельный учёт в прежней программе
(МойСклад, таблицы) ведётся до приёмки. Первая версия плана (только склад, 4 недели) — в истории git.

Решения, на которые опирается пилот: D03 — в минус проводить нельзя; D05 — начальные остатки утверждает не автор;
D06 — аварийный доступ (резервные коды, аварийная команда сервера); D08 — сервер Beget, Linux, SQL Server в Docker;
D54 — копии: полная раз в сутки, журнал каждые 15 минут; D122–D127 — сессии, подтверждение, ограничения входа.

## 1. Участники

| Роль в пилоте | Роль в программе | Что делает |

| Владелец продукта | Владелец | решения по открытым вопросам, утверждает остатки, закрывает период, назначает ответственного |
| Ответственный за пилот | Администратор | приглашает пользователей, следит за «Готовностью к запуску», собирает замечания одним списком в день |
| Старший кладовщик (по складу) | Старший кладовщик | начальные остатки, проведение документов своего склада |
| Кладовщик | Кладовщик | черновики документов, отгрузка, пересчёт инвентаризации |
| Менеджер продаж | Менеджер продаж | заказы, счета, документы клиенту, оплаты (если дано право) |
| Начальник цеха | Руководитель подразделения | производственные заказы, сменные задания, утверждение остатков, табель подразделения |
| Работник цеха | Сотрудник | терминал цеха на телефоне: свои задания и выработка, свой табель и расчётный листок |
| Кадровик | Кадровик | сотрудники, приказы, анкеты по ссылке, документы перед доступом |

## 2. Чек-лист сервера перед стартом

Отмечать в акте подготовки с датой и подписью ответственного.

| № | Проверка | Как проверить | Норма |
|---|---|---|---|
| 1 | Репозиторий кода приватный, у владельца GitHub включена 2FA | настройки GitHub | приватный |
| 2 | Сервер обновлён до последней базы | `cd /opt/kniterp/src/kniterp/deploy/beget && sudo ./update.sh` | без ошибок |
| 3 | Приложение живо | `curl -s https://<домен>/health` | `Healthy` |
| 4 | HTTPS и сертификат | браузер, `monitor.sh` | сертификат действует > 30 дней |
| 5 | Почта (SMTP) в `.env`: SMTP_URL, SMTP_USER, SMTP_PASSWORD, SMTP_FROM | «Забыли пароль» на странице входа → письмо пришло | письмо за 1 мин |
| 6 | Мастер-ключ: копия в сейфе (бумага или флешка), не в почте и не в мессенджере | акт | есть |
| 7 | Резервные копии идут по расписанию | `ls /opt/kniterp/backup/enc` — свежая полная за сутки, журнал за 15 мин | есть |
| 8 | Отпечатки копий пишутся (аудит 12.10) | `cat /opt/kniterp/backup/enc/SHA256SUMS` | строка на каждую копию |
| 9 | Внешнее хранилище копий (rclone) | `rclone ls <remote>` | копии есть |
| 10 | Восстановление проверено | `./restore.sh <полная.enc> <журналы…>` в `kniterp_restore` | итоговые счётчики > 0, CHECKDB без ошибок |
| 11 | Мониторинг шлёт письма | временно остановить приложение на 3 мин → письмо | пришло письмо |
| 12 | Вход на сервер только по ключу | `docs/operations.md`, раздел «Вход на сервер» | пароль отключён |
| 13 | Аварийный доступ проверен | резервные коды Владельца распечатаны и в сейфе | есть |

## 3. Перенос данных

Основной путь — **мастер переноса из МойСклад** (раздел «Каталог» → «МойСклад»): проверка связи, предпросмотр, загрузка
номенклатуры, контрагентов, складов, цен и остатков на дату «всё или ничего», отчёт расхождений и повторная сверка остатков.
Остальное — шаблонами Excel (кнопка «Excel» → «Скачать шаблон» на странице раздела). Повторная загрузка не дублирует.

| Данные | Откуда | Где в программе | Проверка после загрузки |
|---|---|---|---|
| Реквизиты, юрлица, расчётные счета | вручную | «Организация» | печать счёта — реквизиты верны |
| Подразделения и должности | штатное расписание | «Структура» | дерево совпадает |
| Сотрудники | кадровый учёт; паспорт, адрес, телефон — **анкетой по ссылке** (D125) | «Сотрудники» → Excel; «Ссылка для заполнения данных» | заполненность карточек |
| Пользователи | список «кто входит в программу» с ролями | «Пользователи» → «Добавить» (письмо со ссылкой) | все вошли с 2FA |
| Номенклатура, модификации, цены | МойСклад | мастер переноса | количество и цены совпадают |
| Контрагенты, договоры | МойСклад / договоры | мастер переноса, «Контрагенты» | ИНН без ошибок |
| Склады | МойСклад | мастер переноса / «Склады» | — |
| Начальные остатки | инвентаризация на дату старта | «Начальные остатки» → Excel, утверждает второй человек | «Сверка» без расхождений |
| Остатки денег | банк, касса на дату старта | «Деньги» → начальные остатки | совпадает с выпиской |
| Долги покупателей и поставщикам | акты сверки | ввод остатков расчётов | акт сверки совпадает |

Персональные данные вносит сам сотрудник по анкете (ссылка на 4 часа), кадровик проверяет и принимает. Согласие на обработку
ПДн подписывается при первом входе (D227).

## 5. Памятки по ролям

### Всем
1. Первый вход — по ссылке из письма (или переданной лично): придумайте пароль и подключите приложение-аутентификатор
   (Яндекс Ключ, Google Authenticator). Ссылка действует 72 часа; потерялась — попросите новую у администратора.
2. При первом входе подпишите паролем документы перед доступом (согласие на ПДн, правила работы, неразглашение).
3. «Пароль и сессии» (меню профиля) — видны ваши устройства, чужое можно завершить. Если включено «одно устройство»,
   вход на новом устройстве через 30 секунд закрывает старое — это нормально.
4. Вопрос или ошибка — «Поддержка» на панели вверху: раздел подставится сам. Помощник (Ника или Книт) отвечает на вопросы
   по работе в программе.

### Кладовщик / Старший кладовщик
1. «Складские документы» → новое поступление, перемещение, списание → строки (вручную, сканером или из Excel).
   Провести и сторнировать может Старший кладовщик своего склада.
2. Остаток в минус не уйдёт; отгрузить больше, чем в заказе, нельзя (аудит 12.10).
3. Ошибка в проведённом документе — «Сторнировать» с причиной и новый документ; документы не удаляются.
4. Перед концом месяца: черновики проведены или отменены, инвентаризация проведена.

### Менеджер продаж
1. «Заказы покупателей» → клиент, строки (цена подставится по соглашению), «Подтвердить». Цена ниже допустимой — нужно
   право и причина. Повторный заказ — «Создать по образцу».
2. Счёт, документы клиенту, отгрузка и оплата — из карточки заказа. Кредитный лимит и просрочка блокируют подтверждение.

### Начальник цеха / работник цеха
1. Начальник: производственные заказы, сменные задания, табель своего подразделения, утверждение остатков чужого автора.
2. Работник: терминал цеха на телефоне — свои задания, отметка выработки, «почему не выполнено»; свой табель и листок.

### Кадровик
1. «Сотрудники» → карточка → «Ссылка для заполнения данных» — письмо сотруднику; данные от сотрудника — «Принять» или
   «Отклонить» с причиной.
2. Приказы (приём, перевод, отпуск, увольнение); увольнение блокирует вход сразу.

### Администратор
1. «Пользователи» → «Добавить»: почта, роль, область (склад или подразделение) — письмо с приглашением уходит само.
2. «Ограничения входа» для цеха и склада: одно устройство, IP-адрес интернета фабрики («Добавить мой текущий адрес»),
   часы работы. Опасные действия (роли, блокировка, токены API, ограничения) просят повторно ввести пароль — это нормально.
3. «Журнал входов» раз в неделю; «Поддержка» — ответ в течение рабочего дня.

### Владелец
1. «Готовность к запуску» — что не сделано перед стартом.
2. Утверждение начальных остатков, все отчёты и журналы.
3. Закрытие месяца: «Сверка» → «Проверка целостности» → записать отпечаток → «Закрытие периода»
   (открыть назад — только с причиной, попадёт в журнал аудита).
4. Резервные коды 2FA и копия мастер-ключа — в сейфе.

## 6. Критерии приёмки пилота

1. Весь пилотный срок операции пилотных участков — только в knitERP.
2. Остатки по инвентаризации конца месяца совпадают с учётными, расхождения объяснены документами инвентаризации.
3. «Сверка» без расхождений и «Проверка целостности» без нарушений на дату закрытия; отпечаток записан.
4. Период закрыт Владельцем; зарплата за месяц рассчитана и совпадает с параллельным расчётом.
5. Восстановление копии проверено хотя бы раз за пилот (раздел 2, п. 10).
6. Нет ошибок «нет доступа» у пользователей, которым доступ нужен по роли.
7. Замечания закрыты или перенесены в план доработок с согласия Владельца.

## 7. Как сообщать о проблемах

Ответственный за пилот раз в день присылает Владельцу один список: раздел, что делали, что ожидали, что получили, снимок
экрана (без паролей и чужих персональных данных). Владелец пересылает список сессии № 1 — она распределяет по модулям.
Срочно (не работает вход, не проводится документ, потерялись данные) — сразу, не дожидаясь вечера.
