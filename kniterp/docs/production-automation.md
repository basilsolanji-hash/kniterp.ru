# Производство: меньше ручного ввода (D413)

Цель — чтобы мастер, рабочий и контролёр выбирали и подтверждали, а не печатали и не считали в уме. Принципы:
программа подставляет то, что можно вычислить из уже введённых данных; подставленное всегда видно и меняется одним касанием;
то, что влияет на деньги и баллы (виновник брака, причина невыполнения), программа подсказывает, но не выбирает сама.

## Уже было до D413

| Где | Что делает программа |
|---|---|
| Создание заказа | Заказы по заказу покупателя одной кнопкой; склад НЗП по умолчанию; изделие ищется по коду |
| Материалы | Выдача заполняется по норме (план − выдано + возвращено) |
| Выпуск | Количество = готово к выпуску; расход материалов предлагается по норме |
| Терминал | QR-код этапа открывает страницу отметки; кнопка «Всё: N»; причина неполной отметки — из списка |
| Сменные задания | «Повторить задания прошлого дня» (D408); факт и процент считаются по отметкам |
| Баллы | Отсутствие по табелю не штрафуется автоматически (D409) |
| Выработка | Кадры получают выработку из отметок, повторная работа исключается сама (D410) |

## Реализовано в D413

| № | Где | Было | Стало | Экономия |
|---|---|---|---|---|
| 1 | Карточка заказа, «Ход работ» | Выбрать этап и набрать количество | Этап, где есть что отмечать, и количество «сколько можно» подставлены; после каждой отметки — заново | Обычная отметка — одно нажатие «Отметить» |
| 2 | Сменные задания, назначение | Выбрать этап и посчитать план | После выбора заказа — первый свободный этап маршрута и план = свободное количество; в списке этапов видно «свободно N» | Не нужно открывать заказ, чтобы узнать остаток |
| 3 | Сменные задания | Недовыполненное вчера — пересчитать и назначить заново | «Перенести недовыполненное»: остаток (план − факт) тем же сотрудникам, с комментарием; выполненные не переносятся; в журнале — «перенос недовыполненного» | Минуты мастера каждое утро |
| 4 | Терминал цеха | Рабочий помнит своё задание и считает остаток | Кнопка «По заданию: N» — остаток своего сменного задания на этот заказ и этап | Ошибки «отметил больше задания» |
| 5 | Брак и переделка (терминал и карточка) | Причина печатается каждый раз | Частые причины организации за полгода — подсказки в поле и кнопки на телефоне | Набор текста на телефоне; одинаковые формулировки для отчётов |
| 6 | Виновник брака | Поиск в списке всей фабрики | Сначала «Работали по заказу», затем остальные; сам виновник не подставляется | Поиск в длинном списке |

Проверки: интеграционный тест `Less_manual_input_prefills_plans_carries_remainder_and_suggests_reasons`, сквозные проверки
подстановки количества и плана в `ProductionOrderE2ETests`.

## Безопасность и границы

- Подсказки и списки строятся только из данных своей организации и только для тех, у кого есть право на действие
  (виновник — с правом `production.defect.culprit`, D412).
- Подстановка не отправляет ничего сама: запись появляется только по нажатию пользователя, все проверки сервера (поток этапов,
  блокировка заказа, права) прежние.
- Подставленное значение не затирает то, что пользователь уже набрал.

## Предложения за пределами модуля (переданы сессиям, в production.md)

| Модуль | Предложение |
|---|---|
| Закупки | Заказ поставщику из «Планирования материалов» одной кнопкой: дефицит по заказам → строки заказа с поставщиком по умолчанию |
| Склад | Приёмка по заказу поставщику с подстановкой количества «ожидается»; сканер штрихкода в поле позиции |
| Сотрудники | Табель «Я» по дням, где есть отметки работы на терминале (черновик для кадровика) |
| Продажи | Отгрузка готовой продукции по заказу покупателя после выпуска — с подстановкой выпущенного количества |
