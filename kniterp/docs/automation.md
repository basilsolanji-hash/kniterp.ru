# Автоматизация процессов и сокращение ручного ввода (D119)

Версия 1.0 от 12.10.2026. Цель — пользователь вводит только то, чего программа не может знать сама: решение, количество, цену
по договорённости. Всё остальное — подставляется, считается, загружается из файла или делается по событию.

## 1. Что уже автоматизировано
| Процесс | Как работает |
|---|---|
| Реквизиты контрагента и юрлица | По ИНН из справочника (DaData), не вручную |
| Документы на основании | Заказ покупателя → счёт, отгрузка, возврат; заказ поставщику → поступление, возврат |
| Этапы заказа покупателя | Меняются сами по событиям: счёт, оплата, отгрузка, производство (D110) |
| Разноска оплат | Автоматически по самым старым долгам, зачёт авансов (D85) |
| Закупка под производство | Потребность в пряже по производственным заказам → заказы поставщикам (производство) |
| Сменные задания | «Повторить задания прошлого дня» (D408) |
| Номера, даты, НДС, суммы | Считаются программой |
| Справочники из МойСклад | Загрузка в фоне (D310) |

## 2. Предложения
Оценка: **эффект** — сколько ручной работы убирает; **объём** — трудоёмкость. Очерёдность — по эффекту на единицу труда.

| № | Предложение | Что убирает из ручной работы | Эффект | Объём | Волна |
|---|---|---|---|---|---|
| А1 | **Загрузка банковской выписки** (формат 1С «Клиент-банк», есть у всех банков РФ) | Ручной ввод каждой оплаты покупателя и поставщику: плательщик находится по ИНН, счёт/заказ — по номеру в назначении платежа, оплата сразу разносится; повторная загрузка той же выписки не дублирует оплаты | очень высокий | средний | 1 |
| А2 | **Автозаказ поставщику по неснижаемому остатку** | Ежедневную проверку остатков и набор заказов: позиции ниже минимума → черновики заказов, сгруппированные по основному поставщику позиции (D309), количество — до минимума с учётом уже заказанного | высокий | малый | 1 |
| А3 | **«Повторить заказ»** покупателя и поставщику | Повторный набор тех же строк постоянному клиенту: новый черновик с теми же позициями, ценами по текущему прайсу | высокий | малый | 1 |
| А4 | **Вставка строк из Excel** в заказ (код или артикул или штрихкод ⇥ количество ⇥ цена) | Построчный ввод больших заказов, присланных клиентом таблицей; нераспознанные строки показываются, а не теряются | высокий | малый | 1 |
| А5 | **Умные значения по умолчанию** в новом заказе | Выбор склада, юрлица, договора и отсрочки при каждом заказе: берутся из последнего заказа этого контрагента и действующего договора | средний | малый | 1 |
| А6 | **Автозакрытие заказа**: полностью отгружен и оплачен → «Закрыт» | Ручное закрытие сотен заказов и «висящие» заказы в отчётах | средний | малый | 2 |
| А7 | **Загрузка УПД поставщика из XML** (формат ФНС, приходит по ЭДО) | Ручной ввод поступления и счёта-фактуры: строки сопоставляются по штрихкоду и артикулу поставщика (D309) | очень высокий | большой | 2 |

| А9 | **Регулярные операции** (аренда, связь, лизинг) по расписанию | Ежемесячный ввод одинаковых расходов: черновик создаётся сам, пользователь подтверждает | средний | средний | 2 |
| А10 | **Напоминание покупателю об оплате** письмом со счётом за N дней до срока и при просрочке | Ручные звонки и письма должникам | средний | средний | 2 |

## 3. Правила для всех автоматизаций
- Автоматика **ничего не проводит молча**: создаёт черновики или делает то же, что пользователь, — с проверкой прав, в журнал аудита
  с пометкой «автоматически» и с указанием источника (файл выписки, правило, расписание).
- Повторный запуск безопасен (идемпотентность): та же выписка, тот же файл УПД, то же правило — без дублей.
- Всё, что программа не распознала, показывается списком «нужно решение», а не пропускается.
- Каждая автоматизация отключается в настройках организации.
