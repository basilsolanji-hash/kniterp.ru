## Р1. Закрытие строк-услуг заказа покупателя (D301)

**Сейчас.** Сессия № 4 сделала точечно (с тестами, `CatServicesTests`):
- услугу нельзя провести складским документом (`item.service_not_stocked`);
- отгрузка и возврат по заказу строки-услуги пропускают;
- резерв и «Доступно» для услуги не считаются (`SalesOrderLineDto.Stocked = false`).

**Что остаётся.** Отгруженная стоимость, долг покупателя, «Отгружено» в списке заказов, главный экран и печать УПД считаются по отгрузкам.
Строки-услуги в них не попадают:
- заказ «Свитер + Доставка» после отгрузки свитера остаётся «частично отгружен»;
- доставка не входит в долг покупателя и в УПД.

**Решение (D301).**
1. Документ «Акт оказания услуг» (или «Реализация услуг») по заказу: строки-услуги, цена и НДС из заказа, проведение без движений склада.
2. Учёт акта в отгруженной стоимости, долге, статусе отгрузки (строка-услуга закрыта актом) и в динамике продаж.
3. УПД по отгрузке и акту вместе — один документ со строками товаров и услуг (графа «код вида товара» для услуги — «--»).

Те же правила для заказа поставщику: акт поставщика на услуги (доработка, доставка) — в долге поставщику.

**Сделано сессией № 4 (D354)** по поручению заказчика, миграция `CatServiceActs`. Новые виды складского документа без движений склада:
«Акт оказания услуг» (`ServiceAct`, «АУ») по заказу покупателя и «Акт услуг поставщика» (`SupplierServiceAct`, «АП») по заказу поставщику —
кнопки «Акт на услуги» и «Акт услуг поставщика» в карточках заказов, черновик на незакрытое количество строк-услуг, цена и НДС из заказа.
Строки — только услуги своего заказа, не больше заказанного (сервис и триггер базы); отгрузка и поступление услугу по-прежнему не принимают.
Акт считается как отгрузка (поступление) — `StockOperationKinds.OrderKind`: статус и «Отгружено» заказа, суммы, долг, расчёты, акт сверки,
главный экран, «Товары и реализации», журнал счетов-фактур, выгрузка в 1С («Услуги»). «Прибыльность»: себестоимость услуги — по актам
поставщика, иначе 0. УПД печатается и по акту; отгрузка и акты заказа одной датой — один УПД (графа 1б у услуги «--»). Тесты — `CatServiceActTests`.

## Р2. Отгрузка и возврат комплектов (D302, D303)

**Сейчас.** Комплект в заказе покупателя и в счёте — одной строкой по своей цене. Складские документы комплект не принимают
(`item.bundle_not_stocked`). Отгрузка по заказу с комплектом останавливается с сообщением `sales.order.bundle_shipment`, чтобы
комплект не ушёл без списания компонентов.

**Решение.** Сессия № 4 подготовила доменную часть:
- `BundleExpansion.Expand` и `ExpandLines` в `Domain/Catalog/Bundles.cs`, `BundleService.SpecsAsync` — состав для разворота;
- `BundleExpansion.Cost` — себестоимость для «Прибыльности».

Что нужно в документах сессии № 1:
1. **Строки разворота.** При создании отгрузки по заказу строка комплекта разворачивается в строки компонентов. В строке
   документа хранится, из какого комплекта и какого количества она получена: новые колонки `BundleItemId`, `BundleQuantity`
   в `stock_document_lines`. Тогда состав фиксируется на момент отгрузки, а изменение состава не меняет проведённые документы.
2. **Учёт отгруженного.** «Отгружено» по строке комплекта = `BundleQuantity` его строк разворота. На этом основаны статус
   отгрузки, резерв (`Reservations`), отгруженная стоимость, долг и `EnsureReturnWithinShippedAsync`.
3. **Возврат.** Возврат покупателя по заказу возвращает компоненты — тем же разворотом с теми же количествами.
4. **УПД.** По отгрузке — одна строка комплекта по его цене (графа «код товара» — код комплекта); разбивка видна в самом
   документе отгрузки.
5. **Себестоимость.** В «Прибыльности» себестоимость комплекта считать через `BundleExpansion.Cost`.
6. **Резерв.** Резерв заказа с комплектом держит компоненты: `Reservations` разворачивает строки комплектов.
7. **Закупки.** Заказ поставщику комплект не принимает (`purchase.order.bundle`): закупаются компоненты.

После этого строку `sales.order.bundle_shipment` в `SalesService.CreateShipmentAsync` можно убрать.

**Сделано сессией № 4 (D352)** по поручению заказчика, миграция `CatBundleShipment`. Отгрузка разворачивает комплект в строки
компонентов с `BundleItemId`/`BundleQuantity` (уникальность строк — позиция + комплект); в черновике меняется количество комплекта
целиком (`StockDocumentService.SetBundleAsync`, `RemoveBundleAsync`). «Отгружено» по строке комплекта — количество комплектов
один раз на документ (`BundleLines.InOrderTerms`): статус, резерв, суммы, долг, журнал счетов-фактур, акт сверки, главный экран,
выгрузка в 1С. Возврат — пропорционально отгруженному составу (`BundleExpansion.Proportional`). УПД — комплект одной строкой; в выгрузке в 1С — компонентами с разложенной суммой (D356). Привязка акта к УПД отгрузки не меняется задним числом (D355).
«Прибыльность» — себестоимость по фактически ушедшим компонентам. Резерв держит компоненты. Отказ `sales.order.bundle_shipment` убран.
Тесты — `CatBundleShipmentTests`.

## Р3. Цена ниже минимальной в заказе покупателя (D305)

**Сейчас.** У позиции есть минимальная цена продажи (`Item.MinPrice`), видна только с правом «Цены и суммы».

**Решение.** Предупреждать, не запрещать. Продажа ниже минимальной цены бывает осознанной (распродажа, брак), поэтому
нужен видимый сигнал, а не отказ.
1. В `SalesOrderLineDto` — флаг `BelowMinimum` (`TradeRules.BelowMinimum(цена после скидки строки, item.MinPrice)`).
2. В карточке заказа — подсветка строки и подсказка «ниже минимальной цены N».
3. При подтверждении заказа — предупреждение в ответе со списком строк; подтверждение не блокируется.
4. В аудит подтверждения — пометка «ниже минимальной цены: коды».

## Р4. Количество в упаковках в строках документов (D307)

**Сейчас.**
- У товара есть упаковки (`item_packs`: единица, коэффициент, штрихкод).
- `Packs.ToBase(упаковок, коэффициент, точность)` пересчитывает упаковки в основные единицы и не пропускает дробный остаток там, где он недопустим.
- `PackService.ScanAsync(code)` по штрихкоду упаковки возвращает позицию и количество.

**Решение.** В строках складских документов, заказов покупателя и поставщику нужен ввод «N упаковок» рядом с количеством.
В строке хранится количество в основных единицах — движения и остатки не меняются. Скан штрихкода упаковки добавляет к строке
её коэффициент. Печать УПД — в основных единицах, графа 2/2а без изменений.

## Подсказки сессиям № 1–3 (от сессии № 4)

**Всем.**
1. **Один DbContext на вкладку Blazor — отклонённая правка не должна оставаться в нём.**
   - Если сервис меняет сущность, а проверка после этого бросает `BusinessRuleException`, изменение остаётся в контексте.
   - Следующее сохранение на той же вкладке молча его записывает.
   - Сессия № 4 воспроизвела это тестом на ценах (`CatPricingTests`).
   - Правило: все проверки — до изменения сущностей; иначе `try { … } catch { db.DiscardChanges(); throw; }`, как в `PostAsync`.
2. **Новые типы номенклатуры: услуга `10` и комплект `11` на складе не хранятся.**
   - Проверка: `ItemTypes.IsStocked(type)`, `ItemTypes.NotStocked`.
   - Выбор строк складских документов: `StockEntry.ActiveItems(db, org, stockedOnly: true)`.
   - Проверка перед проведением: `StockEntry.EnsureStockedAsync`.
   - Триггеры базы отклоняют движения и партии по ним (`THROW 51300`). Без проверки в сервисе пользователь увидит сбой, а не сообщение.
3. **Слияние ветки `claude/catalog-products`.** Будет конфликт в `KnitErpDbContextModelSnapshot.cs`: принять обе стороны и проверить
   `dotnet ef migrations has-pending-model-changes`. Миграции каталога: `CatServices`, `CatBundles`, `CatPricing`, `CatPacks`.
   Конфигурации каталога — в `CatalogConfigurations.cs`; правки в `Configurations.cs` минимальны.
4. **Skills в `.claude/skills/`.**
   - `kniterp-stage` — порядок сдачи этапа;
   - `kniterp-translations` — поиск недостающих переводов и слияние be/kk/uz;
   - `kniterp-e2e` — стенд Playwright со входом через 2FA, повторяемые сценарии, 1440 и 390 px.

**Сессии № 1 (склад, продажи, закупки).**

## Р5. Подстановка поставщика позиции в заказ поставщику (D309)

**Сейчас.** У позиции есть поставщики (`item_suppliers`): артикул и наименование у поставщика, основной поставщик.
`ItemSupplierService.MainAsync(itemId)` возвращает основного поставщика и последнюю цену закупки без НДС.

**Решение.** При добавлении строки в заказ поставщику:
1. **Цена.** Если у позиции есть строка с этим поставщиком, подставлять его последнюю цену. Если нет — закупочную цену карточки, как сейчас.
2. **Печать.** Показывать артикул поставщика рядом с кодом в строке заказа и в печатной форме заказа.
3. **Выбор поставщика.** В новом заказе предлагать поставщика, который у большинства позиций основной (подсказка, не обязательность).

## Подсказки сессиям № 1–3: этап 4 и шаг «настройки + 50 000 позиций» (от сессии № 4)

- **Список номенклатуры листается в базе (D313).** `ItemFilter` получил `Skip`; `Take` по-прежнему не больше 2000. Если ваш экран или выбор
  позиции показывает «первые N», а позиций может быть больше — передавайте `Skip`/`Take` и показывайте `ItemListDto.Total`. Поиск по коду,
  наименованию и артикулу идёт по столбцу `items.SearchKey` (верхний регистр, двоичное сравнение) — свои запросы поиска позиций
  стройте так же: `EF.Property<string>(i, ItemSearch.Column).Contains(text.ToUpperInvariant())`, это в 5–10 раз быстрее LIKE по трём столбцам.
- **API `/api/v1/items` исправлен:** раньше читались первые 2000 позиций и листались в памяти — дальше 2000-й ничего не отдавалось.
  Если у вас есть такой же приём `Paged(list.Items, offset, limit)` поверх списка с ограничением `Take` (контрагенты, заказы,
  складские документы в `ApiV1`) — проверьте ту же ошибку на больших данных.
- **Настройки каталога (D312):** `CatalogSettingsService.GetAsync()` → `IsEnabled(type)`. Выключенные услуги или комплекты лучше скрывать
  и в ваших формах выбора позиции (заказ покупателя, заказ поставщику, техкарта), чтобы список не предлагал ненужное. Запрет сделан
  только на ручное создание и смену типа; документы с уже созданными позициями не блокируются.
- **Фоновая загрузка МойСклад (D310)** — `MoySkladImportWorker`, отключается ключом `MoySklad:WorkerDisabled` (как `Webhooks:Disabled`).
  Таблицы `external_links` и `external_import_runs` общие для будущих 1С и маркетплейсов: новую внешнюю систему добавляйте значением
  `ExternalSystem`, а не новой таблицей связей.
- **E2E-skill:** `start-app.sh` больше не убивает вызывающую оболочку (`pkill -f "[K]nitErp\.Web"`) и ждёт выхода прежнего экземпляра.
  Строка вкладок `.tabs` теперь переносится (на 390 px вкладки страниц с 5+ вкладками давали горизонтальную прокрутку).
- **Сообщение «Позиция сохранена.»** на странице номенклатуры содержит ссылку на новую позицию: список листается страницами, новая
  позиция может быть не на текущей. В своих e2e открывайте её через `page.locator('.flash').getByRole('link', …)`.

- **Долгоживущий DbContext вкладки — новые средства.** `db.ReloadAsync(entity)` — перечитать отслеживаемую сущность (значения и rowversion):
  запрос с отслеживанием возвращает СТАРУЮ копию, если она уже в контексте. Нужны перед изменением строк, которые меняет кто-то ещё
  (счётчики, статусы фоновых задач). Счётчики номеров — под `db.LockAsync("…{org}")` внутри транзакции. После неуспешного
  `SaveOrConflictAsync` вызывайте `db.DiscardChanges()` — общий `SaveOrConflictAsync` сам этого не делает (не меняли: его зовут все модули).
- Фото в фиде (D324): `IFeedPhotoLinks` (Web, Data Protection) — образец подписанных ссылок без входа, если понадобятся для печатных форм.

## Подсказки сессиям: точки сохранения, поле файла, e2e со складом (от сессии № 4, D326, 12.10.2026)
- **Частичный откат внутри транзакции.** `db.SavepointAsync("имя")` / `db.RollbackToSavepointAsync("имя")` (+ `DiscardChanges`) — для пакетной
  обработки «строка — всё или ничего» без отказа от всей пачки (пример — `MoySkladImportService.ItemAsync`). Кэши в памяти, которые строка
  успела изменить, откатывайте сами (там — список `_undo`). Вне транзакции метод бросает исключение.
- **Сессии № 1 (склад):** на `/stock-documents/{id}` при 390 px поле «Загрузить строки из Excel» давало прокрутку вбок — исправлено общим CSS
  (`input[type=file]` не шире экрана) в `App.razor`, разметку страницы не трогали. Проведение поступления без «Причины» отклоняется
  («Укажите причину операции.») — поле стоит в форме черновика; если это не задумано, сделайте причину по умолчанию для поступления.
- **e2e со складскими данными:** `scenarios/cat-step9-doc-labels.mjs` сам создаёт склад, поступление со строками и проводит его — можно взять
  как заготовку для своих сценариев (позиции — `E2E_ITEMS="код1,код2"`).

## Подсказки сессиям: типы полей, ошибки МойСклад (от сессии № 4, D328–D329)
- **Сессии № 1 (заказ покупателя):** `CustomFieldType` пополнился `LongText = 6`, `Link = 7`, `Counterparty = 8`. Для `SalesOrder` они пока запрещены

- **Ссылки от пользователя** выводите только после `Uri.TryCreate` + схема http/https (иначе `javascript:` в href) — так сделано в `Normalize`.
- **Всем:** характеристики модификаций теперь с типом (`Characteristic.Normalize`): при создании модификаций в своих сценариях

## Подсказки сессиям: ресурсы, кодировка, диагностика внешних систем (от сессии № 4, D330)
- **Ввод пользователя не должен задавать объём работы сервера без предела.** Циклы по шагу (`for (v = from; v <= to; v += step)`)
  с десятичным шагом могут не завершиться (`v + step == v`) — считайте число шагов заранее и идите по счётчику; декартово
  произведение и любые «развороты» — проверяйте размер ДО построения. Найдено и исправлено в каталоге (диапазоны, модификации).
- **Кириллица в базе — только nvarchar.** `HasColumnType("varchar(…)")` годится для цифр, ИНН, кодов и латинских идентификаторов;
  русский текст (названия разделов, причины) в varchar превращается в «???» без ошибки. Проверьте свои конфигурации.
- **Диагностика внешней системы для пользователя:** по одному запросу на раздел, ограничение времени на раздел, текст ответа
  внешней системы без секретов (образец — `MoySkladImportService.ProbeAsync` и `MoySkladHttpClient.ErrorTextAsync`).
- **Поле с кнопкой, которая зависит от его значения:** `@bind:event="oninput"`, иначе кнопка включится только после ухода из поля,
  и первый клик по ней потеряется.

## Подсказки сессиям: публичный адрес, регрессия e2e (от сессии № 4, D331–D332)
- **Ссылки «наружу» (письма, фиды, печатные формы с QR) стройте от `App:PublicUrl`, а не от `Request.Host`.** При `AllowedHosts=*` Host
  задаёт клиент; если результат кэшируется — его увидят другие. Предложение для эксплуатации (не менял, затрагивает монитор):
  в `deploy/beget/compose.yml` задать `AllowedHosts: "${KNITERP_DOMAIN};localhost;127.0.0.1"` — после проверки, что `monitor.sh`
  ходит на localhost.
- **Регрессия в браузере одной командой:** `E2E_DIR=… bash .claude/skills/kniterp-e2e/run-all.sh` — все `scenarios/cat-*.mjs` по очереди,
  итог «ок/ОШИБКА/время», логи — `$E2E_DIR/regress/`. Свои сценарии называйте по шаблону своей сессии и добавьте аналогичный запуск.
- **Сессии № 1:** доп. поля заказов покупателя в МойСклад тоже есть (`attributes` у customerorder) — при загрузке заказов можно взять
  разбор значений из `MoySkladImportService.RawValueAsync` (справочник, контрагент, дата).

## Подсказки сессиям: заголовки внешних API, синхронизация версий (от сессии № 4, D334–D335)
- **Точное значение заголовка:** типизированные заголовки .NET (`MediaTypeWithQualityHeaderValue`) переформатируют значение
  («a;b» → «a; b»). Если внешний API сравнивает строку дословно (МойСклад: только `application/json;charset=utf-8`), задавайте
  `TryAddWithoutValidation` и проверяйте в тесте `Headers.NonValidated["…"]`, а не `GetValues` (он снова форматирует).
- **Двусторонний обмен:** после своей записи во внешнюю систему не помечайте объект «синхронизированным», если не уверены, что до записи
  там не было чужих правок (сравните версию до записи с версией последнего чтения) — иначе чужие правки потеряются навсегда.
- **Массовые запросы:** внешний API может принять пакет с ошибками по отдельным элементам (HTTP 200) — считайте успехи по элементам.
