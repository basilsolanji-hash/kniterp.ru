# ТЗ: база знаний помощника на 4000 ответов и обучение помощника

Версия 1.0 от 12.10.2026. Исполнитель — отдельная сессия Claude, ветка `claude/assistant-kb`. Номера решений — **D900–D999**.
Основание — `docs/tz/assistant.md` (D116): персонажи Ника и Книт, формат статей, правила сбора знаний из интернета.

## 1. Цель
Помощник отвечает на вопросы сотрудников фабрики быстро и верно: как сделать что-то в knitERP и как устроено производство
трикотажа и одежды. Для этого — база из **4000 готовых проверенных ответов**, поиск, который находит нужный ответ по вопросу
своими словами, и цикл «обучения»: помощник учится на вопросах, на которые не нашёл ответа.
«Обучение» здесь — не дообучение модели ИИ: это наполнение и проверка базы, синонимы, тестовый набор вопросов и отчёт о пробелах.
Без подключённой модели ИИ помощник показывает готовый ответ из базы; с моделью — формулирует по найденным ответам, со ссылкой на них.

## 2. Правила совместной работы (обязательно)
1. Ветка от актуальной базы:
   ```
   git fetch origin claude/fervent-volta-3pn88r
   git checkout -B claude/assistant-kb origin/claude/fervent-volta-3pn88r
   ```
   Перед каждым этапом — `git fetch origin && git merge origin/claude/fervent-volta-3pn88r`. Сливает в базу сессия № 1.
2. Свой код: `Application/Workspace/Knowledge/**`, `IndustryKnowledge.cs`, поиск помощника в `HelpCenter.cs` и `AssistantService.cs`
   (только поиск и источники ответа), панели «Справка» и «Помощник», тест `KnowledgeBaseTests`, папка `docs/kb/`.
   Персонажи, права, данные организации (D117 «ИИ по данным») — не трогать.
3. Номера решений — D900–D999. Чужие: D86–D199 база, D90–D99 и D400–D499 производство, D200–D299 «Сотрудники», D300–D399 каталог,
   D500–D599 контрагенты, D600–D699 CRM, D700–D799 «Разработка», D800–D899 проверка интерфейса.
4. Статьи модулей (`production-*.json`, `hr-*.json`, `catalog-*.json`) пишут их сессии; эта сессия пишет ответы о работе в программе
   по всем модулям, сверяясь с их кодом и экранами, и не переписывает чужие статьи — дополняет своими файлами.
5. Каждый этап: ответы → проверка → тесты (`KnowledgeBaseTests`, тестовый набор вопросов, все модульные и интеграционные) →
   e2e (помощник находит ответ, телефон 390 px) → D9xx → коммит → пуш → отчёт по-русски с «Готовность проекта» и «Следующие 3 шага».

## 3. Формат ответа (D900)
Новый вид записи — «вопрос-ответ», файлы `Knowledge/qa-<раздел>.json` (встраиваются в сборку, как статьи):
```json
{ "id": "qa-sales-0001", "section": "Программа · Продажи", "question": "Как выставить счёт покупателю по заказу?",
  "variants": ["сделать счёт из заказа", "счёт на оплату клиенту", "где кнопка счёт"],
  "answer": ["Откройте заказ покупателя → «Счёт на оплату» ...", "Если кнопки нет — нет права «Продажи: изменение»..."],
  "links": ["sales-orders"], "roles": ["Менеджер продаж", "Бухгалтер"], "sources": ["экран knitERP, версия 12.10.2026"],
  "reviewed": "2026-10-12", "level": "basic" }
```
- `answer` — 1–6 абзацев, по шагам, с названиями кнопок как на экране; `links` — адреса экранов программы для кнопки «Открыть».
- Отраслевые и правовые ответы — `sources` с адресом и датой обращения (правила `assistant.md` § 4.3: два независимых источника,
  норма — из официального текста, пересказ своими словами, пометка «проверьте актуальную редакцию» у меняющихся норм).
- Загрузчик `IndustryKnowledge` читает и статьи, и вопросы-ответы; `KnowledgeBaseTests` проверяет формат, уникальность `id`,
  дубли вопросов, рабочие `links`, обязательные источники у отраслевых и правовых ответов.

## 5. Поиск и «обучение» (D910–D929)
- Поиск по вопросу своими словами: нормализация (регистр, ё/е), русская морфология (стемминг или словарь основ), синонимы
  отрасли и программы (`Knowledge/synonyms.json`: «УПД — универсальный передаточный документ», «ОТК — контроль качества»…),
  исправление опечаток, вес вопроса и вариантов выше текста ответа. Учитывать экран, с которого спрашивают (раздел выше в выдаче).
- Права: ответы с `roles` показываются всем, но ссылка «Открыть» — только если у пользователя есть доступ к экрану.
- **Тестовый набор** `docs/kb/eval.json`: 400 вопросов, как их задают люди (с ошибками и разговорно), с ожидаемым `id`.
  Цель: верный ответ первым — не меньше 85 %, в первой тройке — не меньше 95 %. Тест считает и падает ниже порога.
- **Цикл обучения:** кнопки «Помогло / Не помогло» под ответом; вопросы без ответа и с «Не помогло» сохраняются **без персональных
  данных** (текст вопроса после маскировки телефонов, почт, ФИО; экран; дата), раз в неделю — отчёт «чего не хватает» для ответственного
  (экран «Справка → Пробелы базы», право Администратора). Из отчёта — новые ответы и синонимы.
- Скорость: поиск по 4000 ответам — до 50 мс; индекс строится один раз при запуске; размер встроенных файлов — до 8 МБ.

## 6. Этапы и сроки
1. D900–D902: формат, загрузчик, тесты формата, синонимы, тестовый набор 100 вопросов — и первые 500 ответов (вход, продажи, склад).
2. 2000 ответов: все разделы программы.
3. 3000: отраслевые разделы с источниками.
4. 4000: требования, ошибки; тестовый набор — 400 вопросов, пороги точности выполнены.
5. Цикл обучения: «Помогло / Не помогло», отчёт пробелов.
Переводы ответов на be/kk/uz — после проверки русского текста, отдельным этапом (машинный перевод с вычиткой носителем).

## 7. Приёмка
4000 ответов в репозитории, тест формата и тест точности поиска — зелёные; помощник на телефоне и компьютере находит ответ и открывает
экран; отчёт пробелов работает; все тесты проекта зелёные; отчёт владельцу по-русски с «Готовность проекта» и «Следующие 3 шага».
