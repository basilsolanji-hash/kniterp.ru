# ТЗ: knitERP по подписке — коммерческий запуск для других фабрик

Версия 1.0 от 12.10.2026. Исполнитель — отдельная сессия Claude, ветка `claude/saas-subscription`. Номера решений — **D1000–D1099**.

## 1. Цель и очерёдность
knitERP — коммерческий продукт. **Первая очередь — собственная фабрика владельца** (пилот, `docs/pilot.md`): всё, что делает эта
сессия, не должно мешать её работе. **Вторая очередь — продажа другим фабрикам по подписке** (облако, ежемесячная оплата):
регистрация, тарифы, оплата, ограничения тарифа, поддержка, юридические документы, выход клиента со своими данными.
Страны: Россия, Беларусь, Казахстан, Узбекистан (D60); первая — Россия.

## 2. Правила совместной работы (обязательно)
1. Ветка от актуальной базы:
   ```
   git fetch origin claude/fervent-volta-3pn88r
   git checkout -B claude/saas-subscription origin/claude/fervent-volta-3pn88r
   ```
   Перед каждым этапом — `git fetch origin && git merge origin/claude/fervent-volta-3pn88r`. Сливает в базу сессия № 1.
2. Свой код: `Domain/Subscriptions`, `Application/Subscriptions`, страницы `Components/Pages/Billing*`, `Components/Pages/Platform*`,
   публичные страницы `/signup`, `/pricing`, миграции с префиксом `Sub…`. Чужой код — только точки из п. 9, с тестом и записью в
   `docs/sessions/subscription.md` (раздел «Вопросы к базе»).
3. Номера решений — D1000–D1099. Чужие: D86–D199 база, D90–D99 и D400–D499 производство, D200–D299 «Сотрудники», D300–D399 каталог,
   D500–D599 контрагенты, D600–D699 CRM, D700–D799 «Разработка», D800–D899 интерфейс, D900–D999 база знаний.
4. `CLAUDE.md`: организация — из сессии, чужая → 404; права на сервере; аудит; `rowversion`; деньги `decimal(19,4)`; никаких
   реальных ключей платёжных систем, паролей и персональных данных в репозитории и тестах (ключи — в настройках сервера, шифрование
   мастер-ключом, как у почты и интеграций).
5. Каждый этап: код → модульные и интеграционные тесты → e2e .NET Playwright → переводы be/kk/uz → D10xx → коммит → пуш → отчёт
   по-русски с «Готовность проекта» и «Следующие 3 шага». Скиллы: `kniterp-stage`, `kniterp-tests`, `kniterp-translations`, `kniterp-e2e`.

## 3. Что уже есть (не дублировать)
- Многоорганизационность: каждая фабрика — `Organization`, данные изолированы по `OrganizationId`, чужая → 404; один пользователь
  может быть в нескольких организациях. Создание организации с Владельцем — `OrganizationService.CreateWithOwnerAsync`.
- Роли и права (D112), 2FA (обязательна для Владельца и Администратора), журнал аудита с подписью цепочки, резервные копии (D08),
  API и вебхуки (D88), почта (D81), языки и страны (D60), установка на Beget VPS (`deploy/beget`).
- Поддомены клиентов (`fabrika.kniterp.ru`) — отложены (D503); решить в этом ТЗ (п. 6.6).

## 4. Модель продукта (D1000)
- **Платформа** — владелец продукта (оператор сервиса). **Клиент** — организация-фабрика с подпиской.
- **Тарифы** (цены задаёт владелец в консоли, в рублях; для BY/KZ/UZ — в их валюте позже):
  | Тариф | Для кого | Пользователей | Модули |
  |---|---|---|---|
  | Старт | ателье, мини-цех | до 3 | склад, продажи, закупки, деньги, каталог |
  | Фабрика | цех до 50 человек | до 15 | + производство, сотрудники, CRM, интеграции |
  | Про | фабрика | до 50 | + «Разработка», API без ограничений, приоритетная поддержка |
  | Индивидуальный | крупные | договорённость | всё, свой сервер по желанию |
  Цены — в консоли, не в коде. Оплата за месяц или год (скидка за год — настройка). Пробный период — 14 дней на тарифе «Фабрика».
- **Ограничения тарифа** проверяются на сервере: число активных пользователей, доступ к модулям (раздел меню скрыт, сервис
  отвечает «доступно в тарифе …»), лимиты API и места под файлы. Превышение — понятное сообщение с кнопкой «Сменить тариф»,
  данные не теряются.
- **Собственная фабрика владельца** — организация с признаком «внутренняя»: без оплаты и ограничений.

## 5. Этап 1 — подписки и тарифы (D1001–D1009)
- Сущности: `Plan` (код, название, цена месяц/год, валюта, лимиты, модули, архив), `Subscription` (организация, тариф, состояние:
  пробная / активна / просрочена / приостановлена / закрыта, период, дата следующего списания, `rowversion`), `SubscriptionEvent`
  (история — только вставка: создана, продлена, тариф сменён, оплата прошла/не прошла, приостановлена, возобновлена).
- Сервис `EntitlementService`: «модуль доступен?», «можно добавить пользователя?» — с кэшем на минуту; вызывается в точках п. 9.
- Состояния: просрочка оплаты → 7 дней льготного периода с баннером у Владельца → «только чтение» (просмотр, отчёты, выгрузка
  данных; создание и проведение документов запрещены на сервере) → через 60 дней — «приостановлена» (вход только Владельцу
  к выгрузке данных и оплате) → через 180 дней — удаление данных после письменного уведомления (настройка, по договору).
- Внутренняя организация владельца и организации с «Индивидуальным» тарифом — без автоматической приостановки.

## 6. Этап 2 — регистрация и первый запуск (D1010–D1019)
1. Публичные страницы без входа: `/pricing` (тарифы, сравнение, вопросы), `/signup` — регистрация: email, название фабрики,
   ИНН (реквизиты подтягиваются по ИНН, D60), страна, телефон (по желанию), согласие с офертой и политикой обработки ПДн
   (две отдельные отметки, ссылки на документы версии, дата и IP — в журнал).
2. Подтверждение email (ссылка 24 ч), защита от роботов без сторонних сервисов, отслеживающих пользователей (лимиты по IP,
   задержка, простая задача), не больше 3 регистраций с одного адреса в сутки.
3. Создаётся организация, Владелец, пробная подписка; вход → мастер «Первые шаги»: юрлицо и счёт, склады, единицы, загрузка
   номенклатуры и контрагентов из Excel или МойСклад (готовые функции), приглашение сотрудников, подключение 2FA.
4. Демо-данные по желанию (отдельная организация «Демо-фабрика» с вымышленными данными, можно удалить одной кнопкой).
5. Письма: приветствие, пробный период заканчивается (за 3 дня и в день), оплата прошла, оплата не прошла.
6. **Адрес клиента (D503):** решение — единый адрес `app.kniterp.ru` с выбором организации после входа (уже есть) — по умолчанию;
   поддомен `<фабрика>.kniterp.ru` — опция тарифа «Про» (только имя организации на странице входа, данные изолированы как прежде).

## 7. Этап 3 — оплата (D1020–D1039)
- Платёжный провайдер РФ с рекуррентными платежами и чеками 54-ФЗ (ЮKassa или CloudPayments — выбор владельца; код —
  через интерфейс `IPaymentGateway`, провайдер подключается адаптером, в тестах — заглушка). Данные карт к нам не попадают
  (оплата на странице провайдера, PCI DSS — у провайдера).
- Юрлицам — **оплата по счёту**: счёт и акт от юрлица владельца продукта (используются печатные формы базы: счёт, УПД),
  подписка активируется по загруженной банковской выписке (D119 А1) или вручную в консоли.
- Уведомления провайдера (webhook) — проверка подписи, идемпотентность, повтор — без двойного продления.
- Чеки, счета, акты — в разделе «Оплата и тариф» у Владельца клиента; там же смена тарифа (доплата пропорционально дням),
  отмена автопродления, история платежей.

## 8. Этап 4 — консоль платформы (D1040–D1059)
Отдельный раздел только для операторов платформы (новое системное право `platform.admin`, вход только с 2FA, отдельный журнал):
список клиентов (тариф, состояние, пользователи, последний вход, объём данных), продление и скидки вручную с причиной,
тарифы и цены, рассылка служебных уведомлений, обращения в поддержку всех клиентов (с согласия клиента на доступ),
метрики: MRR, отток, конверсия пробных, активность по модулям. **Оператор не видит данные клиента** (документы, остатки, деньги):
доступ к данным — только по временному разрешению Владельца клиента («Доступ поддержки на 24 часа»), каждое действие — в журнал клиента.

## 9. Точки соприкосновения с базой (согласовать до кода)
1. `IAccessGuard`/меню: проверка модуля тарифа (`EntitlementService`) — одна точка в базе, а не в каждом сервисе.
2. Приглашение пользователя (`UserAccessService.InviteAsync`) — лимит пользователей тарифа.
3. Режим «только чтение» — общий фильтр в базе: запрет изменяющих действий при просроченной подписке (кроме оплаты и выгрузки).
4. Выгрузка всех данных организации (Excel и машиночитаемый архив) — для выхода клиента и по 152-ФЗ.
5. Создание организации — общее с текущим созданием (`CreateWithOwnerAsync`).

## 6а. Полная автоподготовка организации при покупке (дополнение 12.10.2026)
- Отдельная база данных на клиента **не создаётся**: все клиенты в одной базе SQL Server, изоляция по `OrganizationId` (уже
  действует: составные ключи, 404 на чужое). Отдельный сервер/база — только опция «Индивидуального» тарифа, отдельным решением.
- Сейчас `OrganizationService.CreateWithOwnerAsync` создаёт: организацию, Владельца (ссылка на пароль и 2FA, 72 ч), системные роли,
  единицы, причины операций, этапы и правила продаж, юрлицо, вид цены, статьи ДДС, ставки НДС. Запуск — только командой на сервере.
- Сделать точку расширения `IOrganizationSeeder` в базе: каждый модуль (производство, «Сотрудники», каталог, CRM, «Разработка»,
  продажи) регистрирует свои начальные данные; все выполняются в одной транзакции с созданием; ошибка любого — откат целиком.
  Повторный вызов не дублирует данные (для уже созданных организаций — команда «дозаполнить настройки по умолчанию»).
- Создание по оплате/регистрации: сайт → подтверждение email → организация + пробная подписка за ≤ 5 с; письмо с входом.
  Повторный платёж или двойное нажатие не создаёт вторую организацию (идемпотентный ключ регистрации).
- Тест приёмки: новая организация → каждый пункт меню открывается без ошибок и без пустых обязательных справочников;
  тест изоляции: данные новой организации не видны другим и наоборот.

## 6б. API для сайта kniterp.ru (запрос сессии сайта, 12.10.2026; входит в этап 2, D1010–D1019)
Сайт делает отдельная сессия: репозиторий `basilsolanji-hash/knitERP`, ветка `claude/upbeat-gauss-npdbne`, папка `site/`
(форма — `site/src/pages/signup.html`, логика — `site/src/static/js/site.js`), подробное ТЗ серверной части — `site/docs/backend-tz.md`
(при расхождении с этим разделом — согласовать с сессией № 1 до кода).
1. `/api/public/*` — без входа и cookie; CORS только для `https://kniterp.ru`; лимиты по IP в существующем `AddRateLimiter`.
2. `GET /api/public/challenge` — задача против роботов: подписанный одноразовый токен, SHA-256, сложность 18 бит.
3. `POST /api/public/leads` — заявка в CRM внутренней организации владельца + письмо на hello@kniterp.ru.
4. `GET /api/public/company-lookup` — реквизиты по ИНН через существующий сервис (D60).
5. `POST /api/public/signup` — всегда 202 (не раскрывать, есть ли почта). Новая почта → `SubPendingSignup` и письмо со ссылкой на 24 ч;
   почта уже есть → письмо «у вас уже есть вход». Не больше 3 регистраций с IP в сутки.
6. Журнал согласий `SubConsent` — только вставка (триггер): документ, версия (2026-10-12), дата UTC, IP, браузер.
7. `app.kniterp.ru/signup/confirm`: пароль → `CreateWithOwnerAsync` + пробная подписка 14 дней на «Фабрике» в одной транзакции →
   обязательная 2FA → мастер «Первые шаги». Письмо-приветствие и напоминания о конце пробного периода.
8. `/pricing` и `/signup` в приложении → 301 на страницы сайта.
Тесты: модульные, интеграционные (изоляция, 202 для существующей почты, лимит IP, одноразовость токена и ссылки), e2e регистрации.
Собственная фабрика владельца работает без изменений. Реальных ключей и адресов почтового сервера в репозитории нет.

## 10. Юридическое и безопасность (D1060–D1079)
- Документы (тексты готовит юрист владельца, программа хранит версии и согласия): публичная оферта / лицензионный договор SaaS,
  политика обработки ПДн (152-ФЗ: оператор — клиент, обработчик — владельцу продукта; поручение обработки в оферте),
  соглашение об уровне обслуживания (SLA: доступность 99,5 %, резервное копирование ежедневно, хранение копий 30 дней).
- Хранение данных граждан РФ — на серверах в РФ (242-ФЗ); для других стран — отдельное решение (D10xx).
- Изоляция клиентов проверяется автоматическим тестом: для каждого сервиса — данные чужой организации → 404.
- Нагрузочный тест: 100 организаций × 20 пользователей на одном сервере — время ответа экранов не хуже 1 с.
- Мониторинг и страница состояния сервиса; резервные копии с проверкой восстановления раз в месяц.

## 11. Этапы

2. Регистрация и мастер первых шагов (п. 6).
3. Оплата картой и по счёту (п. 7).

5. Юридические документы, согласия, выгрузка данных, тесты изоляции и нагрузки (п. 10).

## 12. Приёмка
Новая фабрика сама регистрируется, работает 14 дней, оплачивает картой или по счёту, получает чек и акт; при неоплате — льготный
период, «только чтение», приостановка; данные изолированы (тест), выгружаются по кнопке; консоль показывает клиентов и выручку;
собственная фабрика владельца работает без ограничений и без изменений. Все тесты зелёные; отчёт по-русски с «Готовность проекта»
и «Следующие 3 шага».
