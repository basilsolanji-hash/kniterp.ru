# Модуль «Разработка»: предложения по автоматизации и сокращению ручного ввода

Версия 1.0 от 11.10.2026. Шестая сессия, решения D790–D799 (`docs/decisions.md`; D710–D789 оставлены этапам 2–7 по ТЗ).
Основание — запрос владельца продукта: «подготовить предложения по оптимизации процессов с целью автоматизации и минимизации
ручного ввода данных пользователем, далее реализовать все».

## 1. Где сейчас теряется время
Разбор этапа 1 по шагам пользователя (создать модель → заполнить задание → назначить людей → вести по стадиям → приложить файлы):

| Шаг | Сколько ввода сейчас | Что повторяется |
|---|---|---|
| Новая модель | 6–12 полей | Одни и те же исполнители почти на каждой модели; дата запуска считается в уме по нормативам |
| Задание | 10 полей | Размерный ряд, состав, маркировка и уход у одной категории почти всегда одинаковые |
| Похожая модель | всё заново | Модели коллекции отличаются цветом и названием |
| Коллекция на сезон | 20–60 моделей по одной | Список моделей уже есть в Excel у дизайнера |
| Стадии | нажатие на каждом переходе | Программист приложил программу — значит, пора вязать образец |
| Контроль | открывать доску и искать своё | Ответственный не узнаёт, что модель пришла к нему |
| Поиск | через меню и отбор | Номер «М-00012» называют в разговоре |
| Фото с телефона | снять, найти файл, загрузить | Образцовщица у машины с телефоном |
| Отчёты | выписывать в Excel вручную | Список моделей с датами и ответственными |

## 2. Предложения (все реализованы, кроме раздела 3)

| № | Предложение | Сколько ввода экономит | Решение |
|---|---|---|---|
| 1 | **Шаблоны задания по категории.** В настройках у категории (свитер, шапка…) — размерный ряд, цветовая гамма, состав, маркировка, уход. Новая модель получает их сразу; в карточке — кнопка «Заполнить из шаблона категории» для пустых полей. | до 5 полей на модель | D790 |
| 2 | **Исполнители по умолчанию.** В настройках — дизайнер, дессинатор, конструктор, технолог, программист отдела. Незаполненные роли новой модели заполняются ими (если человек ещё активен). | до 5 полей | D791 |
| 3 | **Плановый запуск считается сам.** Не указан — сегодня + сумма нормативов включённых стадий (без «Рисунка», если рисунка нет). Отключается в настройках. | 1 поле и расчёт в уме | D792 |
| 4 | **Название по умолчанию.** Пустое название → «Категория — коллекция — заказчик». Можно сразу сохранить и переименовать позже. | 1 поле | D792 |
| 5 | **«Создать похожую».** Копия модели: карточка, задание, исполнители; новая модель — на стадии «Идея», файлы и история не копируются. | вся карточка | D793 |
| 6 | **Excel: загрузка и выгрузка моделей.** Шаблон, проверка файла целиком, протокол ошибок по строкам, всё или ничего; незнакомая коллекция создаётся (с правом настроек). Выгрузка списка с отборами. | коллекция на сезон одним файлом | D794 |
| 7 | **Автопереход по событию.** Загружена программа машины на стадии «Программа» → модель сама переходит на следующую стадию (обычно «Образец»); загружен рисунок на стадии «Идея» или «Задание» у модели с рисунком → стадия «Рисунок». Пишется в историю с пометкой «автоматически»; отключается в настройках. | 1 действие на переход | D795 |
| 8 | **Уведомления в колокольчике.** «Модели на вашей стадии: N», «Просрочено у вас: N», главному технологу — «Ждут утверждения: N». | ежедневный просмотр доски | D796 |
| 9 | **Быстрый поиск по номеру и названию модели** из общей строки поиска. | переходы по меню | D796 |
| 10 | **Фото с камеры телефона.** Для видов «Фото» и «Эскиз» поле выбора файла открывает камеру телефона. | поиск файла в галерее | D797 |
| 11 | **Подсказка следующего шага.** На карточке — что нужно сделать на текущей стадии и чего не хватает (нет задания, нет рисунка, нет программы, не назначен ответственный). | вопросы «что дальше» | D798 |

## 3. Автоматизация следующих этапов (заложена в ТЗ, делается вместе с этапами 2–7)
- Доли цветов рисунка — расчётом по файлу-сетке (одна клетка — одна петля), а не вручную (этап 2).
- Время вязки — из программы машины или по последнему образцу; задача программисту — сама по кнопке «Рисунок готов» (этап 2).
- Списание пряжи на образец — складской документ создаётся из образца, без повторного ввода (этап 3).
- Табель мер — из шаблона категории, градация заполняет все размеры от базового (этап 4).
- Себестоимость — цены пряжи из каталога и последних закупок, расценки — из «Сотрудников» (этап 5).
- Передача в производство — позиция каталога, модификации и черновик техкарты одной кнопкой (этап 6).
- Отчёты — из данных модуля, без ручного свода (этап 7).
