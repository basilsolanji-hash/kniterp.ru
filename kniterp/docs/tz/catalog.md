# ТЗ: «Товары, услуги, комплекты» и подготовка к обмену с МойСклад — для отдельной сессии Claude

Версия 1.0 от 11.10.2026. Исполнитель — четвёртая сессия Claude. Параллельно работают:
- сессия № 1 — склад, продажи, закупки, деньги, API, теги, обсуждения (ветка `claude/fervent-volta-3pn88r`);
- сессия № 2 — производство (`claude/kniterp-repository-study-2u528m`);
- сессия № 3 — сотрудники (`claude/hr-employees`).

## 0. Правила совместной работы (обязательно)
1. Своя ветка от актуальной `claude/fervent-volta-3pn88r`: `claude/catalog-products`. Не пушить в чужие ветки и не сливать их без просьбы владельца.
   ```
   git fetch origin claude/fervent-volta-3pn88r
   git checkout -B claude/catalog-products origin/claude/fervent-volta-3pn88r
   ```
2. Номера решений в `docs/decisions.md` — **только D300–D399**. Чужие номера: D86–D199 у сессии № 1, D90–D99 у сессии № 2, D200–D299 у сессии № 3.
3. Свой код — каталог: `Domain/Catalog`, `Application/Catalog`, страницы номенклатуры, `Application/Exchange/MoySklad` (новое). Производство не трогать: техкарты, производственные заказы, выпуск. Кадры тоже не трогать.
4. Складские, продажные и закупочные сервисы (`StockDocumentService`, `SalesService`, `PurchaseService`, `CustomerInvoiceService`, печать УПД) принадлежат сессии № 1. В них можно вносить только **точечные проверки**, перечисленные в этапах ниже, каждую с тестом и пометкой в коммите. Всё остальное оформить запросом к сессии № 1 через владельца.
5. Миграции — с префиксом `Cat…`, например `dotnet ef migrations add CatServices -p src/KnitErp.Infrastructure -o Persistence/Migrations`. Применённые миграции не редактируются; SQL вне модели (триггеры) — через `EXEC(N'...')`. При слиянии ветки сессии № 1 будет конфликт в `KnitErpDbContextModelSnapshot.cs`: принять обе стороны и проверить `dotnet ef migrations has-pending-model-changes -p src/KnitErp.Infrastructure`.
6. Соблюдать `CLAUDE.md`:
   - права на сервере через `IAccessGuard`;
   - организация берётся из сессии, чужое → 404;
   - `rowversion` на изменяемых сущностях;
   - журнал аудита на изменения;
   - справочники не удаляются, а архивируются;
   - один DbContext на вкладку Blazor;
   - допущения помечаются как Dxx.
7. Никаких реальных токенов МойСклад, паролей и персональных данных в коде и тестах. Клиент МойСклад в тестах — подделка (fake) с записанными примерами JSON.
8. Каждый шаг: реализация → модульные и интеграционные тесты (SQL Server) → e2e Playwright (1440 px и 390 px, 0 ошибок JS) → коммит → пуш → отчёт по-русски с разделами «Готовность проекта» и «Следующие 3 шага».
9. Строки интерфейса — через `L("...")` с переводами be/kk/uz; тест `TranslationCoverageTests` должен проходить.

## 1. Что уже есть (не ломать)
- **`Item`** (`Domain/Catalog/CatalogEntities.cs`):
  - код (уникален навсегда), наименование, тип `ItemType` (1–6, 9);
  - единица, ставка НДС, группа, артикул;
  - страна происхождения, ГТД, ТН ВЭД, вес, объём;
  - неснижаемый остаток, закупочная цена, архив.
- **Модификации:** `ParentItemId` + `VariantKey`, характеристики `Characteristic` и `ItemCharacteristicValue`, сервис `ModificationService`. Модификация — отдельная позиция со своим остатком.
- **Группы** `ItemGroup` (дерево), **штрихкоды** `ItemBarcode` (EAN-13/8, Code 128 и др.), **виды цен** `PriceType` и **цены** `ItemPrice`, **свои справочники** `UserCatalog`, **доп. поля**, **фото**.
- Сервисы `CatalogService`, `NomenclatureService`, `ItemExchangeService` (Excel), страницы `CatalogPage`, `ItemCardPage`, `CatalogSettingsPage`.
- Партии пряжи (`StockBatch`) и складской учёт (сессия № 1): остаток = сумма движений.
- Ограничение в базе `ck_items_type` = `[Type] IN (1, 2, 3, 4, 5, 6, 9)` — расширять новой миграцией.
- Обсуждения и теги на карточке позиции уже работают (`TaggedEntity.Item`). Новых значений `TaggedEntity` не требуется: услуга и комплект — это тоже `Item`.

## 2. Этап 1 — услуги (D300+)
Услуга продаётся и покупается, но не хранится на складе: пошив по образцу, доработка, доставка, упаковка подарочная, ремонт оборудования.
- `ItemType.Service = 10`, название «Услуги». Расширить `ck_items_type`.
- Правила услуги:
  - нет остатка, партий, веса и объёма, неснижаемого остатка и штрихкода маркировки;
  - единица — из справочника, по умолчанию «усл. ед.» (код ОКЕИ 876) или «ч» (356);
  - ставка НДС обязательна;
  - признак предмета расчёта для чека — «услуга».
- В карточке и списке: фильтр «Товары / Услуги / Комплекты»; у услуги скрыты складские блоки.
- Точечные проверки в документах сессии № 1 (с тестами):
  - услугу нельзя провести складским документом (поступление, списание, перемещение, отгрузка, инвентаризация, начальные остатки) — `BusinessRuleException("item.service_not_stocked")`;
  - заказ покупателя или поставщику, счёт и УПД услугу **принимают**;
  - резерв и «Доступно» для услуги не считаются;
  - при отгрузке по заказу строки-услуги пропускаются: они закрываются актом или УПД, а не складом.
- Отчёты остатков и оборотов услуги не показывают.

## 3. Этап 2 — комплекты (D3xx)
Комплект — коммерческий набор из нескольких позиций, который продаётся одной строкой: «Набор шапка + шарф», «Комплект детский 3 предмета». Он **не хранится на складе как отдельный товар**: остаток считается по компонентам, при отгрузке списываются компоненты. Это аналог `bundle` в МойСклад. Сборка комплекта как отдельного складского изделия делается через производство (техкарты) и в этот этап не входит.
- `ItemType.Bundle = 11`, название «Комплекты».
- Таблица `bundle_components`: комплект, компонент (`Item`, не услуга и не комплект), количество `decimal(18,6)` > 0, порядок, `rowversion`.
  - Уникальность пары (комплект, компонент); FK и CHECK — в базе.
  - Вложенные комплекты и цикл запрещены.
  - Компонентом может быть модификация.
- Чистая функция в Domain: `BundleExpansion.Expand(bundleId, quantity, components) → [(itemId, qty)]`, с округлением по точности единицы компонента и модульными тестами.
- **Доступность комплекта** = min по компонентам ⌊доступно компонента / количество в комплекте⌋ — на странице и в API.
- **Цена комплекта:** своя цена по видам цен. Показать подсказку «сумма цен компонентов» и скидку набора.
- **Себестоимость** = сумма средних себестоимостей компонентов (только чтение, для отчёта «Прибыльность»).
- Точечные изменения в документах сессии № 1 (с тестами):
  - в заказе покупателя комплект — одна строка;
  - при отгрузке строка комплекта разворачивается в движения компонентов через `BundleExpansion`, в документе видна разбивка;
  - возврат покупателя возвращает компоненты;
  - в счёте и УПД — одна строка комплекта по его цене.
  Если разворот в отгрузке требует больше, чем точечная правка, оформить запрос к сессии № 1, а у себя сдать доменную часть, карточку и API.
- Изменение состава комплекта не меняет проведённые документы: состав на момент отгрузки фиксируется в строках разворота.

## 4. Этап 3 — карточка товара уровня МойСклад
- **Упаковки** (аналог `packs` в МойСклад): «коробка = 12 шт», «мешок = 25 кг». Таблица `item_packs`: единица упаковки, коэффициент к основной единице, свой штрихкод. В документах можно вводить количество в упаковках с пересчётом.
- **Цены:**
  - история цен по датам (`item_price_history`, только вставка);
  - минимальная цена продажи — предупреждение в заказе, если цена ниже (проверку в заказе согласовать с сессией № 1);
  - массовая переоценка: группа или отбор → «+ N %» или «= цена закупки × коэффициент», с предпросмотром и журналом.
- **Поставщики позиции:** поставщик, его артикул, его наименование, последняя цена закупки. Подставляется в заказ поставщику — точечная правка, согласовать с сессией № 1.
- **Маркировка «Честный ЗНАК»** (трикотаж и одежда входят в обязательную маркировку лёгкой промышленности): признак «маркируемый товар», вид продукции `trackingType`, GTIN.
  - В этом этапе — только поля и проверки формата GTIN-14 с контрольной суммой.
  - Работа с кодами маркировки (DataMatrix, ЭДО, ГИС МТ) — отдельное ТЗ позже.
- **Признак предмета расчёта** для чеков (54-ФЗ): товар, услуга, подакцизный — справочное поле, нужное для будущей кассы.
- **Импорт и экспорт Excel** (`ItemExchangeService`): новые колонки — тип (товар, услуга, комплект), упаковки, минимальная цена, GTIN, маркировка. Состав комплектов — на отдельном листе. Старые файлы должны по-прежнему загружаться.
- **API v1** (`docs/api.md`, сессия № 1 ведёт файл): `GET /api/v1/items` возвращает тип, упаковки и состав комплекта; `GET /api/v1/items/{id}/availability` — доступность (для комплекта — по компонентам). Новые методы добавить в `ApiEndpoints` отдельным файлом-расширением, не переписывая существующие.

## 5. Этап 4 — подготовка к обмену с МойСклад (импорт справочников)
Цель — в будущем подключить МойСклад без переделки модели. На этом этапе — **только загрузка справочников из МойСклад в knitERP**. Документы, остатки и двусторонняя синхронизация — следующее ТЗ.

**API МойСклад:** JSON API 1.2, `https://api.moysklad.ru/api/remap/1.2/`.
- Авторизация `Authorization: Bearer <токен>`, заголовок `Accept-Encoding: gzip`.
- Лимиты: не больше 45 запросов за 3 секунды и не больше 5 параллельных запросов на пользователя; при ответе 429 ждать `X-Lognex-Retry-After`.
- Страницы: `limit` до 1000, `offset`.
- Сущности: `entity/productfolder` (группы), `entity/product` (товары), `entity/service` (услуги), `entity/bundle` (комплекты, состав — `components`), `entity/variant` (модификации, `characteristics`), `entity/uom`, `entity/currency`, `entity/country`, `context/companysettings/pricetype` (виды цен).

**Таблица внешних идентификаторов** `external_links` (общая, пригодится для 1С, маркетплейсов и магазина):
- поля: организация, система (`MoySklad=1`; расширяемый список), тип объекта (`Item`, `ItemGroup`, `PriceType`, `UnitOfMeasure`, `Counterparty`), id в knitERP, внешний id (UUID МойСклад), `externalCode`, версия (`updated` из МойСклад), время синхронизации;
- уникальность: (организация, система, тип, внешний id) и (организация, система, тип, id knitERP).

**Сопоставление полей** — оформить таблицей в `docs/moysklad-mapping.md`:

| МойСклад | knitERP |
|---|---|
| `name` | наименование |
| `code` | код (если занят — суффикс и предупреждение) |
| `article` | артикул |
| `externalCode` | внешний код |
| `barcodes` (ean13, ean8, code128, gtin, upc) | штрихкоды |
| `uom` | единица (по коду ОКЕИ, иначе создать) |
| `vat`, `vatEnabled` | ставка НДС |
| `salePrices[].priceType` | виды цен |
| `buyPrice` | закупочная цена |
| `minPrice` | минимальная цена |
| `weight`, `volume` | вес, объём |
| `country` | страна |
| `tnved` | ТН ВЭД |
| `trackingType` | маркировка |
| `paymentItemType` | предмет расчёта |
| `packs` | упаковки |
| `productFolder` | группа |
| `variant.characteristics` | характеристики модификации |
| `bundle.components` | состав комплекта |
| `archived` | архив |

**Обмен:**
- **Клиент:** интерфейс `IMoySkladClient` в Application, реализация в Infrastructure через `HttpClient` (повторы при 429/5xx с паузой, gzip, таймаут), подделка в тестах. Токен хранить зашифрованным (`SecretCipher`, как секреты интеграций), показывать только последние 4 символа.
- **Мастер загрузки** «Настройки → Интеграции → МойСклад»:
  1. ввести токен и проверить его (`GET entity/organization`);
  2. предпросмотр: сколько групп, товаров, услуг, комплектов и модификаций будет создано, обновлено или пропущено, конфликты кодов;
  3. загрузка в фоне с прогрессом;
  4. отчёт с ошибками по строкам и выгрузка отчёта в Excel.
- **Повторная загрузка идемпотентна:** совпадение по `external_links`, затем по `externalCode`, затем по коду или артикулу. Ничего не дублируется; изменённое в МойСклад обновляется; ручные изменения в knitERP не затираются без флага «перезаписать».
- **Безопасность:**
  - только Владелец или Администратор, право `integration.moysklad.manage`;
  - адрес API фиксирован, произвольный URL не принимается (защита от SSRF);
  - ответ ограничен по размеру;
  - журнал аудита: кто, когда, сколько объектов.
- **Будущее (только интерфейсы, без реализации):** `IExternalSync` для двустороннего обмена, вебхуки МойСклад (`entity/webhook`) на изменение товара — описать в `docs/moysklad-mapping.md`, раздел «Следующие шаги».

## 6. Права
- Существующие: просмотр и изменение справочников (`catalog.*`), просмотр цен.
- Новые (D3xx, добавить в матрицу ролей):
  - `catalog.price.edit` — переоценка и история цен;
  - `catalog.bundle.edit` — состав комплектов;
  - `integration.moysklad.manage` — подключение и загрузка МойСклад.
- Через API не выдаются: `integration.moysklad.manage`, переоценка.

## 7. Нефункциональные требования
- Деньги `decimal(19,4)`, количества `decimal(18,6)`, коэффициенты упаковок `decimal(18,6)`, время UTC `datetime2(3)`.
- Список номенклатуры на 50 000 позиций открывается быстрее 1 с: серверные страницы, индексы по коду, артикулу, штрихкоду и группе.
- Загрузка 50 000 товаров из МойСклад укладывается в лимиты API; пакетная запись по 500 позиций в транзакции; прерванную загрузку можно продолжить.
- Телефон 390 px без горизонтальной прокрутки страницы.
- Запросы главного экрана не утяжелять (тест: ≤ 30 запросов).

## 8. Порядок сдачи
Этапы 1 → 2 → 3 → 4, каждый отдельным коммитом с решениями D3xx и тестами. После каждого этапа — краткий отчёт владельцу и готовность к слиянию (сливает сессия № 1 по команде владельца). Если точечная правка в документах сессии № 1 оказалась больше описанной — остановиться и сформулировать запрос владельцу.
