# Загрузка справочников из МойСклад: сопоставление полей (D310, D311)

Сессия № 4, этап 4 ТЗ каталога (`docs/tz/catalog.md`). Код: `Application/Exchange/MoySklad/` (сервис, модели, интерфейс клиента),
`Infrastructure/Exchange/MoySkladHttpClient.cs` (HTTP), `Web/Exchange/MoySkladImportWorker.cs` (фон), страница «Настройки → Загрузка из МойСклад»
(`/exchange/moysklad`). Тесты: `tests/KnitErp.IntegrationTests/CatMoySkladTests.cs` (подделка клиента с записанными примерами JSON).

## Порядок загрузки
Этапы идут по очереди, страницами по 500 строк (комплекты — по 100, с раскрытым составом). После каждой страницы записывается
контрольная точка (этап и смещение): прерванную загрузку можно продолжить кнопкой «Продолжить».

1. `context/companysettings/pricetype` — виды цен;
2. `entity/productfolder` — группы (родители раньше детей);
3. `entity/product` — товары;
4. `entity/service` — услуги;
5. `entity/variant` — модификации;
6. `entity/bundle` — комплекты (компоненты должны быть загружены раньше).

Справочники `entity/uom` и `entity/country` читаются целиком в начале загрузки.

## Поиск существующей позиции (повторная загрузка без дублей)
1. Связь `external_links` по UUID МойСклад;
2. связь по `externalCode` (объект пересоздан в МойСклад — связь переносится на новый UUID);
3. позиция knitERP без связи с тем же **кодом**, затем с тем же **артикулом** — связывается, её значения **не меняются**
   (замечание в отчёте; включите «перезаписать», чтобы обновить).

Для связанной позиции хранится отпечаток (SHA-256) значений, записанных при прошлой загрузке. Если текущие значения в knitERP с ним
не совпадают — позицию правили вручную, и без флага «перезаписать» загрузка её не трогает (замечание «изменена в knitERP»).
Если в МойСклад объект не менялся (поле `updated` то же) — строка пропускается без записи.

## Товары, услуги, комплекты

| МойСклад | knitERP | Правило |
|---|---|---|
| сущность `product` | тип «по умолчанию» (выбирается при запуске: готовая продукция, пряжа…) | у товара МойСклад нет типа knitERP; меняется в карточке |
| сущность `service` | тип «Услуга» | |
| сущность `bundle` | тип «Комплект» | |
| `name` | наименование | обрезается до допустимой длины |
| `code` | код | пустой — `MS-` + начало UUID; занят другой позицией — суффикс `-MS2`, `-MS3`… и замечание |
| `article` | артикул | |
| `externalCode` | внешний код в `external_links` | |
| `barcodes` (`ean13`, `ean8`, `code128`, `upc`) | штрихкоды | недостающие добавляются, свои штрихкоды knitERP не удаляются; занят другой позицией — замечание |
| `barcodes.gtin` | GTIN (блок «Торговля и маркировка») | занят другой позицией — замечание |
| `uom` | единица | по связи, затем по коду ОКЕИ, затем по обозначению; нет — создаётся |
| `vat`, `effectiveVat`, `vatEnabled` | ставка НДС | по проценту на сегодня; `vatEnabled=false` — «Без НДС»; не найдено — пусто (у услуги — основная) |
| `salePrices[].priceType` | цены по видам цен | копейки → рубли; изменение пишется в историю цен с источником «Внешняя система» |
| `buyPrice` | закупочная цена | |
| `minPrice` | минимальная цена | |
| `weight`, `volume` | вес, кг; объём, м³ | у услуг не заполняются |
| `country` | страна происхождения | по цифровому коду ОКСМ |
| `tnved` | ТН ВЭД | только 4, 6, 8 или 10 цифр |
| `trackingType` | вид маркировки | `LP_CLOTHES` → одежда, `SHOES` → обувь и т. д.; `NOT_TRACKED` — без маркировки |
| `paymentItemType` | предмет расчёта | `SERVICE` → услуга, `EXCISABLE_GOOD` → подакцизный товар, остальное → товар |
| `packs` | упаковки | единица упаковки — как `uom`; коэффициент; первый свободный штрихкод; та же единица или дробь для штучной — пропуск с замечанием |
| `productFolder` | группа | по связи с группой |
| `archived` | архив | новая архивная позиция не создаётся; связанная — архивируется / возвращается из архива |

## Модификации и комплекты

| МойСклад | knitERP | Правило |
|---|---|---|
| `variant.product` | родительская позиция | родитель должен быть загружен (этап «Товары») |
| `variant.characteristics[]` (`name`, `value`) | характеристики и их значения | характеристика с тем же названием переиспользуется, иначе создаётся |
| `variant.code` | код модификации | пустой — код родителя + начало UUID |
| `bundle.components[]` (`assortment`, `quantity`) | состав комплекта | компонент — товар или модификация из этой загрузки или ранее связанный; не найден — состав комплекта не меняется, ошибка в отчёте |

## Виды цен и группы

| МойСклад | knitERP |
|---|---|
| `pricetype.name` | вид цены (поиск по связи, затем по названию; не больше 20 видов) |
| `productfolder.name`, `productFolder` | группа и родительская группа (поиск по связи, затем по названию в той же родительской группе) |

## Безопасность (D310)
- Только Владелец или Администратор: право `integration.moysklad.manage`; через API knitERP не выдаётся и не работает.
- Токен: проверяется запросом `GET entity/organization`, хранится зашифрованным (`SecretCipher`), на экране и в журнале — только «…» и последние 4 символа.
- Адрес API зафиксирован (`https://api.moysklad.ru/api/remap/1.2/`), разрешены только перечисленные пути, перенаправления выключены (защита от SSRF);
  ответ ограничен 32 МБ; gzip.
- Лимиты МойСклад: не больше 45 запросов за 3 секунды и 5 параллельных; на 429 — пауза по `X-Lognex-Retry-After`; на 5xx — до 4 попыток с паузой.
- Журнал аудита: подключение, отключение, запуск, продолжение, итог (создано, обновлено, пропущено, ошибок).
- Сбой загрузки любого рода переводит её в «прервана» с безопасным текстом; загрузки, оборванные остановкой приложения, при запуске помечаются прерванными.

## Не загружается (следующее ТЗ)
Остатки, документы, контрагенты, валюты (цены считаются в валюте учёта), изображения, доп. поля (`attributes`), двусторонняя синхронизация.

## Следующие шаги
1. **Двусторонний обмен — `IExternalSync`** (интерфейс в `Application/Exchange/ExternalSync.cs`, без реализации): выгрузка изменённых
   позиций knitERP во внешнюю систему по `external_links` (отпечаток и версия уже хранятся), конфликт — по правилу «кто изменил позже».
2. **Вебхуки МойСклад** (`entity/webhook`, действия `CREATE`, `UPDATE`, `DELETE` на `product`, `service`, `variant`, `bundle`): адрес
   `/api/v1/hooks/moysklad/{секрет организации}`; приход вебхука ставит загрузку одной позиции в очередь (тот же движок, этап по типу).
   МойСклад не подписывает вебхуки — секрет в адресе и повторное чтение объекта по API вместо доверия телу.
3. **Другие площадки** — те же `external_links` и `IExternalCatalogSource`: 1С (`ExternalSystem.OneC`, через EnterpriseData D105),
   Wildberries, Ozon, Яндекс Маркет, Uzum, Kaspi (карточки и цены), сайт (YML-фид). Перечисление `ExternalSystem` расширяемое, числа хранятся в базе.
4. **Остатки и документы из МойСклад** — вводом остатков одним документом «Ввод начальных остатков» (право кладовщика), не прямой записью движений.
